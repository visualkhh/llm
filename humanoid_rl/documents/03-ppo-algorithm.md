# 03. PPO 알고리즘 — Actor-Critic과 Clipped Objective

관련 코드: `rl/ppo.py`

## 강화학습 문제의 기본 틀

```
      관측(observation)
  ┌───────────────────┐
  │                    ▼
  │              [ 정책(policy) ]
  │                    │ 행동(action)
  │                    ▼
  │              [   환경    ]
  │                    │ 보상(reward), 다음 관측
  └────────────────────┘
```

에이전트(정책)는 관측을 보고 행동을 정하고, 환경은 그 행동에 대해 보상과
다음 관측을 돌려줍니다. 목표는 **누적 보상의 기댓값을 최대화**하는
정책을 찾는 것입니다.

## Actor-Critic: 두 개의 신경망

`ActorCritic` 클래스는 신경망 두 개를 갖습니다.

- **Actor(정책망)**: 상태 → "어떤 행동이 좋을지"의 확률분포(정규분포의 평균)
- **Critic(가치망)**: 상태 → "이 상태가 앞으로 대략 얼마나 좋은 상태인지"
  하나의 숫자(가치, value)

왜 둘 다 필요한가: Actor만 있으면 "이 행동이 결과적으로 좋았는지"를
판단할 기준이 없어 학습 신호가 매우 시끄럽습니다(노이즈가 큼). Critic이
"이 상태에서 기대할 수 있는 평균적인 결과"를 기준선(baseline)으로
제공해주면, "평균보다 얼마나 더/덜 좋았는가"(=advantage, 이점)라는 훨씬
깨끗한 학습 신호를 만들 수 있습니다.

### 왜 `ActorCritic` 인스턴스가 `PPO` 안에 두 개(`ac`, `ac_infer`) 있는가

`train.py --pipeline`(04-training-loop.md 참고)으로 "다음 데이터 수집"과
"지금 데이터로 학습"을 서로 다른 스레드에서 동시에 돌릴 때, 두 스레드가
정확히 같은 가중치를 동시에 읽고(추론) 쓰면(경사하강) 애매한 상태의
가중치를 읽어버리는 문제가 생길 수 있습니다. 그래서 실제로 학습되는
`ac`와, 롤아웃 수집에만 쓰는 얼려둔 사본 `ac_infer`를 분리해뒀습니다.
`--pipeline`을 안 쓰면 두 스레드가 애초에 없으므로 이 분리는 그냥
"매 이터레이션 끝에 최신 가중치를 한 번 복사하는" 정도의 사소한
오버헤드로만 존재합니다.

## 확률적 정책 (Stochastic Policy)

Actor는 각 관절에 대해 "평균값" 하나만 내고, 실제 행동은 그 평균을
중심으로 한 정규분포(Gaussian)에서 무작위로 샘플링합니다.

```
action ~ Normal(mean = Actor(state), std = exp(log_std))
```

`log_std`(표준편차의 로그값)는 상태와 무관하게 10개 관절 전체가 공유하는
학습 가능한 파라미터입니다. 학습 초반에는 이 값이 커서(=탐험을 많이 함)
다양한 행동을 시도하다가, 점점 "이런 상황에선 이 행동이 확실히 낫다"는
확신이 쌓이면 스스로 값을 줄여 더 결정론적으로 행동하게 됩니다.

## GAE — "이 행동이 평균보다 얼마나 좋았는가"

`compute_gae` 함수. 핵심 재료는 **TD residual(시간차 오차)**:

```
delta_t = r_t + gamma * V(s_{t+1}) - V(s_t)
```

말로 풀면: "이 행동을 하고 한 스텝 뒤의 상황까지 고려해서 다시 계산해본
가치"에서 "애초에 이 상태에서 Critic이 예측했던 가치"를 뺀 것. 양수면
"예상보다 좋았다", 음수면 "예상보다 나빴다"는 뜻입니다.

GAE는 이 delta들을 미래로 갈수록 `gamma * lambda` 비율로 점점 할인하며
합칩니다:

```
advantage_t = delta_t + (gamma*lambda) * delta_{t+1} + (gamma*lambda)^2 * delta_{t+2} + ...
```

- `gamma`(할인율, 0.99): "당장의 보상"과 "먼 미래의 보상" 중 얼마나
  미래를 중요하게 볼지. 1에 가까울수록 미래를 더 중시.
- `lambda`(0.95): 편향(bias)과 분산(variance) 사이의 절충. 0이면 방금
  설명한 delta_t 하나만 사용(분산은 작지만 Critic의 오차에 편향됨),
  1이면 에피소드 끝까지의 실제 보상을 그대로 사용(편향은 없지만
  들쭉날쭉함, 분산이 큼). 0.95는 실무적으로 널리 쓰이는 절충값입니다.

코드가 시간 역순(`reversed(range(T))`)으로 도는 이유: `advantage_t`가
그 뒤(t+1, t+2, ...)의 delta들에 의존하므로, 미래에서 과거 방향으로
계산해야 이전 계산 결과(`last_gae_lam`)를 재사용해 효율적으로 구할 수
있기 때문입니다.

`returns = advantages + values`는 Critic을 학습시킬 "정답"으로 쓰입니다
— Critic이 애초에 예측했던 값에 "실제로 보니 이만큼 더/덜 좋았다"를
더한 것이 곧 "더 정확해진 가치 추정치"이기 때문입니다.

## PPO의 핵심: Clipped Surrogate Objective

일반적인 정책 경사법은 "advantage가 양수인 행동의 확률은 높이고, 음수인
행동의 확률은 낮춰라"는 식으로 업데이트합니다. 문제는 한 번에 너무 크게
업데이트하면 정책이 망가질 수 있다는 것(한 번의 나쁜 업데이트로 지금까지
배운 걸 다 잃어버릴 수 있음). PPO는 이를 아주 간단한 방법으로 막습니다.

```python
ratio = exp(새 정책의 log확률 - 예전 정책의 log확률)   # 확률의 비율
surr1 = ratio * advantage
surr2 = clip(ratio, 1-eps, 1+eps) * advantage           # eps=0.2 (기본값)
policy_loss = -mean(min(surr1, surr2))
```

`ratio`는 "이 행동을 새 정책이 택할 확률이 예전 정책 대비 몇 배가
됐는가"입니다. `min(surr1, surr2)`의 효과:

- advantage가 양수(좋은 행동)일 때: ratio를 키우고 싶어하지만,
  `1+eps`(1.2)를 넘어서는 순간부터는 더 키워도 손실에 반영되지 않음
  → "이미 충분히 확률을 높였으니 그만해라"
- advantage가 음수(나쁜 행동)일 때: ratio를 줄이고 싶어하지만,
  `1-eps`(0.8) 밑으로는 더 줄여도 반영되지 않음 → "이미 충분히
  낮췄으니 그만해라"

즉 "한 번의 업데이트로 정책이 예전 정책 대비 너무 멀리 가지 않도록"
안전장치를 거는 것이며, 이것이 이름의 Proximal(가까운, 근접한)이 의미하는 바입니다.

## 전체 손실 함수

```python
loss = policy_loss                    # 위에서 설명한 PPO 클립 손실
     + vf_coef * value_loss           # Critic 예측을 returns에 맞추는 회귀 손실 (MSE)
     - ent_coef * entropy             # 엔트로피 보너스 (탐험 장려)
```

- `value_loss`: 평범한 평균제곱오차(MSE). Critic이 정확한 예측을 하도록.
- `entropy`(엔트로피): 정책이 얼마나 "무작위/탐험적"인지의 척도. 이걸
  손실에서 빼는(=최대화하는) 이유는, 정책이 너무 일찍 "이 방법 하나만
  맞다"고 확신해버려서 더 나은 다른 방법을 시도해볼 기회를 잃는 것
  (조기 수렴)을 막기 위함입니다. `ent_coef`(0.01)로 그 중요도를 작게 조절.

## 왜 같은 데이터를 여러 epoch 재사용하는가

환경에서 새 경험을 모으는 것(물리 시뮬레이션 실행)은 신경망 업데이트
한 번보다 훨씬 비쌉니다. 그래서 한 번 모은 데이터(`n_steps * n_envs`개)를
여러 번(`train_epochs`, 기본 4번) 재사용해 최대한 뽑아 씁니다. 다만
같은 데이터를 너무 많이 재사용하면 정책이 그 데이터를 모을 때의 정책에서
너무 멀어질 위험이 커지는데, 이걸 막아주는 것이 위에서 설명한 clip
메커니즘입니다. 그래서 "여러 epoch 재사용 + clip"은 항상 세트로 함께
쓰입니다.

## 로그에서 확인할 지표

`train.py`가 출력하는 값들의 의미:

| 지표 | 의미 | 정상적인 추세 |
|---|---|---|
| `ep_return` | 최근 에피소드들의 평균 누적 보상 | 학습이 될수록 상승 |
| `ep_len` | 평균 에피소드 길이(스텝 수) | 넘어지지 않고 오래 버틸수록 증가 |
| `success` | 최근 에피소드 중 목표 도달 비율 | 0에서 시작해 점차 상승 |
| `policy_loss` | PPO 클립 손실 | 0 근처에서 진동 (자체로는 해석이 어려움) |
| `value_loss` | Critic의 예측 오차 | 대체로 감소, 가끔 튐 |
| `entropy` | 정책의 탐험 정도 | 서서히 감소 (너무 빨리 0에 가까워지면 조기수렴 의심) |
| `kl` (approx_kl) | 이번 업데이트로 정책이 얼마나 바뀌었는지 | 0.01~0.05 근처가 이상적. 너무 크면(예: >0.1) 학습률을 낮출 것 |
| `clip_frac` | 전체 샘플 중 clip이 실제로 작동한 비율 | 적당히(예: 0.1~0.3) 나오는 게 정상. 항상 0이면 클리핑이 무의미하게 작음 |
