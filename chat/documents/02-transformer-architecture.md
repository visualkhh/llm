# 02. 모델 구조 — Decoder-only Transformer (GPT)

관련 코드: `model.py`

이 문서는 `model.py`에 있는 각 클래스가 코드로는 무엇을 하고,
개념적으로는 왜 그렇게 설계됐는지를 설명합니다. 코드 안의 주석과
함께 보면 이해가 더 쉽습니다.

## 전체 그림

```
입력 문자 인덱스 (B, T)
        │
        ▼
┌───────────────────────────┐
│ 토큰 임베딩 + 위치 임베딩   │   "이 글자가 무엇인가" + "몇 번째 글자인가"
└───────────────────────────┘
        │
        ▼
┌───────────────────────────┐
│  Transformer Block × N     │   ┐
│  ┌───────────────────────┐ │   │ n_layer번
│  │ LayerNorm              │ │   │ 반복
│  │ Causal Self-Attention  │ │   │ (더 깊게 쌓을수록
│  │ + 잔차연결(residual)   │ │   │  더 복잡한 패턴 학습)
│  │ LayerNorm              │ │   │
│  │ MLP(Feed-Forward)      │ │   │
│  │ + 잔차연결(residual)   │ │   ┘
│  └───────────────────────┘ │
└───────────────────────────┘
        │
        ▼
┌───────────────────────────┐
│ LayerNorm + Linear(head)   │   각 위치에서 "다음 글자" 점수(logits) 산출
└───────────────────────────┘
        │
        ▼
   (B, T, vocab_size) logits
        │  (softmax)
        ▼
   다음 글자에 대한 확률분포
```

- `B` = batch size (동시에 처리하는 문장 개수)
- `T` = 시퀀스 길이 (문맥 안의 글자 수, 최대 `block_size`)
- `C`(=`n_embd`) = 각 글자를 표현하는 벡터의 차원

## 1) 임베딩 — 숫자를 "의미 있는 벡터"로

`stoi`를 거쳐 나온 정수 인덱스 자체는 아무 의미가 없습니다 ('a'가 39번이라고
해서 39가 특별한 의미를 갖지는 않음). 그래서 각 인덱스를 학습 가능한
`n_embd`차원 벡터로 바꿔주는 **임베딩 테이블**을 둡니다.

- `tok_emb`: "이 문자가 무엇인가"를 나타내는 벡터 (학습되며 점점 의미를 갖게 됨)
- `pos_emb`: "이 문자가 문장에서 몇 번째 위치인가"를 나타내는 벡터

두 개를 더하는 이유: Self-Attention 자체는 순서를 구분하지 못하는 연산
(토큰들의 "집합"처럼 다룸)이기 때문에, 위치 정보를 별도로 주입하지 않으면
"나는 밥을 먹었다"와 "밥은 나를 먹었다"를 구분하지 못하게 됩니다.

## 2) Self-Attention — 문맥을 참고하는 핵심 메커니즘

`CausalSelfAttention` 클래스. GPT를 GPT답게 만드는 가장 핵심적인 부분입니다.

### Query, Key, Value

각 토큰 벡터로부터 세 가지를 계산합니다.

- **Query(Q)**: "나는 지금 무엇을 찾고 있는가?"
- **Key(K)**: "나는 이런 정보를 갖고 있다"라는 꼬리표
- **Value(V)**: 실제로 참고하게 될 내용물

토큰 i의 새로운 표현은:

```
score(i, j) = Q_i · K_j / sqrt(head_dim)     # i가 j를 얼마나 참고할지의 "관련도"
weight(i, j) = softmax_j( score(i, j) )       # 관련도를 확률처럼 정규화
새 표현_i = Σ_j weight(i, j) * V_j            # V들의 가중 평균
```

직관적으로: "i번째 글자를 갱신할 때, 지금까지 나온 글자들(j) 중 나와
관련도(Q·K)가 높은 글자의 정보(V)를 더 많이 반영해서 내 표현을 업데이트한다."

`sqrt(head_dim)`으로 나누는 이유는 벡터 차원이 커질수록 내적값이 커져
softmax가 한쪽으로 너무 쏠리는 것을 방지하기 위한 스케일 조정입니다.

### Causal(인과적) 마스킹

GPT는 문장을 **왼쪽에서 오른쪽으로 순서대로 생성**해야 합니다. 그런데 만약
학습 중에 i번째 글자를 예측할 때 i번째 이후(미래)의 글자까지 볼 수 있다면,
"정답을 미리 커닝"하는 셈이 되어 제대로 된 예측 능력을 배우지 못합니다.

그래서 `score(i, j)`를 계산할 때 `j > i`(미래)에 해당하는 자리는 강제로
`-∞`로 만들어 softmax 후 확률이 0이 되게 합니다. 코드에서는
`F.scaled_dot_product_attention(..., is_causal=True)` 한 줄로 이 마스킹까지
함께 처리됩니다.

```
     j=0  j=1  j=2  j=3      (j: key/value의 위치)
i=0 [ O    X    X    X ]      i=0은 자기 자신만 참고 가능
i=1 [ O    O    X    X ]      i=1은 0,1만 참고 가능
i=2 [ O    O    O    X ]      i=2는 0,1,2만 참고 가능
i=3 [ O    O    O    O ]      i=3은 전부 참고 가능
```

### Multi-Head (여러 개의 머리로 나누어 보기)

`n_embd` 전체를 하나의 attention으로 처리하지 않고, `n_head`개의 작은
부분공간(각 `head_dim = n_embd / n_head`차원)으로 나눠 **독립적으로 병렬**
attention을 수행한 뒤, 결과를 다시 이어붙입니다(`out_proj`로 섞음).

왜 나누는가: 각 head가 서로 다른 종류의 관계에 특화되도록 학습될 여지를
주기 위해서입니다. 예를 들어 어떤 head는 "바로 이전 글자"에, 다른 head는
"단어의 시작 위치"에, 또 다른 head는 "따옴표나 괄호의 짝"에 집중하는 식으로
분업이 자연스럽게 일어나는 경향이 관찰됩니다 (실제로 무엇을 학습할지는
학습 데이터와 최적화 과정에 의해 결정되며, 사람이 미리 지정하지 않습니다).

## 3) MLP (Feed-Forward Network) — 개별 토큰 가공

`MLP` 클래스. Attention이 "토큰들 사이의 관계"를 파악하는 역할이라면,
MLP는 그렇게 모인 정보를 각 토큰 위치마다 **독립적으로** 더 깊게 비선형
변환하는 역할을 합니다. `n_embd -> 4*n_embd -> n_embd` 구조로, 중간을
넓혔다가 줄이는 것은 GPT 계열의 관례적 설계(더 넓은 중간층이 다양한 패턴을
표현할 여유를 줌)입니다.

Transformer는 "관계 파악(Attention)"과 "개별 가공(MLP)"을 번갈아 쌓아
올려서 점점 더 추상적이고 복잡한 패턴을 표현할 수 있게 됩니다.

## 4) 잔차연결(Residual Connection)과 LayerNorm

`Block` 클래스: `x = x + attn(ln1(x))`, `x = x + mlp(ln2(x))`

- **잔차연결(`x + f(x)`)**: f(x)의 결과를 x에 그대로 더함으로써, 층이
  깊어져도 gradient가 소실되지 않고 잘 전달되게 하고, f가 "무엇을 더할지"만
  학습하면 되므로 최적화가 쉬워집니다. ResNet 등 현대 딥러닝 대부분에서
  쓰이는 핵심 기법입니다.
- **LayerNorm**: 각 토큰 벡터를 평균 0, 분산 1 근처로 정규화해서 학습을
  안정시킵니다. Attention/MLP **이전에** 적용하는 방식(Pre-LN)을 썼는데,
  이는 GPT-2 이후 표준으로 자리잡은 방식이며 원래 Transformer 논문(Post-LN)
  보다 학습이 더 안정적입니다.

## 5) 최종 출력 — logits

Block을 모두 통과한 뒤 `LayerNorm` → `Linear(head)`를 거치면 각 위치마다
`vocab_size` 크기의 점수 벡터(logits)가 나옵니다. 이 점수에 softmax를
적용하면 "다음 글자가 무엇일지"에 대한 확률분포가 됩니다.

학습 시에는 이 확률분포와 실제 정답 글자를 비교해 loss를 계산하고
([03-training.md](03-training.md)), 생성 시에는 이 확률분포에서 실제로
샘플링해 다음 글자를 뽑습니다 ([04-generation.md](04-generation.md)).

## 파라미터 수 감(感) 잡기

기본 설정(`n_layer=4, n_head=4, n_embd=128, block_size=128, vocab_size=65`)
기준 이 모델은 약 **82만 개** 파라미터를 가집니다 (`train.py` 실행 시
`model params: 826,368` 로 출력됨). 실제 GPT-2(small)는 약 1.2억 개,
최신 상용 LLM들은 수십억~수조 개 규모입니다 — 구조는 본질적으로 동일하고,
`n_layer`/`n_embd`/`n_head`/`block_size`와 학습 데이터 양이 커질 뿐입니다.
