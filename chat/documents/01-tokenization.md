# 01. 토큰화(Tokenization) — 글자를 숫자로 바꾸기

관련 코드: `data/prepare.py`

## 왜 필요한가

신경망(neural network)은 오직 숫자(텐서)만 계산할 수 있습니다. "H", "i" 같은
문자를 그대로 행렬 곱셈에 넣을 수 없으므로, 텍스트를 다루는 모든 모델은
가장 먼저 **텍스트 → 정수 시퀀스** 변환 과정을 거칩니다. 이 변환 규칙(및
그 규칙을 구현한 도구)을 **토크나이저(tokenizer)** 라고 부릅니다.

## 이 프로젝트가 쓰는 방식: 문자 단위(character-level)

1. 말뭉치(corpus) 전체에서 등장하는 **모든 고유 문자**를 모읍니다.
   (알파벳, 공백, 줄바꿈, 문장부호 등 — Tiny Shakespeare 데이터는 총 65종)
2. 각 문자에 정수 인덱스를 하나씩 부여합니다.
   ```
   stoi = {'\n': 0, ' ': 1, '!': 2, ..., 'a': 39, 'b': 40, ...}
   itos = {0: '\n', 1: ' ', 2: '!', ..., 39: 'a', 40: 'b', ...}
   ```
3. 문자열을 정수 리스트로, 정수 리스트를 다시 문자열로 변환하는 두 함수
   (`encode`, `decode`)가 곧 토크나이저의 전부입니다.

```
"Hi there" --encode--> [23, 47, 1, 58, 43, 39, 47, 39]
[23, 47, 1, 58, 43, 39, 47, 39] --decode--> "Hi there"
```

## 왜 하필 "문자" 단위인가 (장단점)

| 방식 | 장점 | 단점 |
|---|---|---|
| **문자 단위** (이 프로젝트) | 구현이 극도로 단순, 어휘 수가 작음(수십~수백), 새로운 단어도 문제 없음 | 시퀀스가 매우 길어짐(단어 하나 = 여러 토큰), 모델이 "단어"라는 개념을 스스로 문자 조합에서 학습해야 함 |
| **단어 단위** | 시퀀스가 짧아짐 | 어휘가 수만~수십만 개로 커짐, 처음 보는 단어(oov) 처리가 곤란 |
| **서브워드(BPE 등)** — 실제 GPT/Claude가 사용 | 짧은 시퀀스 + 처음 보는 단어도 조각으로 표현 가능 | 구현이 더 복잡(빈도 기반 병합 알고리즘 필요) |

문자 단위를 고른 이유는 순전히 **교육적 단순함** 때문입니다. 원리를 이해한
뒤에는 `tiktoken`, `sentencepiece` 같은 라이브러리로 BPE 토크나이저를 붙이는
것도 좋은 다음 실습입니다 ([05-next-steps.md](05-next-steps.md) 참고).

## 학습/검증 데이터 분리

```python
train_text = text[: int(n * 0.9)]   # 앞 90%
val_text = text[int(n * 0.9):]      # 뒤 10%
```

- **train**: 실제로 가중치를 업데이트하는 데 쓰는 데이터
- **val(검증)**: 학습에는 전혀 사용하지 않고, 모델이 "외운 것"이 아니라
  "패턴을 배웠는지"를 확인하는 용도. `train.py`가 이 값을 계속 감시하면서
  가장 좋은 체크포인트를 자동으로 저장합니다. ([03-training.md](03-training.md) 참고)

## 저장되는 파일들

`python3 data/prepare.py` 실행 후 `data/` 폴더에 생성되는 것:

- `train.bin`, `val.bin` — 토큰화된 정수 배열 (uint16 바이너리, numpy로 빠르게 로드)
- `meta.pkl` — `{vocab_size, stoi, itos}` 딕셔너리. 학습(`train.py`)과
  생성(`chat.py`) 양쪽에서 "같은 문자↔숫자 매핑"을 쓰기 위해 반드시 공유되어야
  하는 파일입니다. (체크포인트에도 함께 저장되어 다닐 수 있게 되어 있습니다)

`.bin` 파일을 numpy의 `memmap`으로 읽는 이유는 [03-training.md](03-training.md)의
"메모리 효율" 부분에서 설명합니다.
